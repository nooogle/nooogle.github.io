How I made the voice clips

Every sound in the app (the 46 basic kana, the ones with dakuten like が, and combination sounds like きゃ) is its own little clip. Here's how I made them with Google Cloud's Chirp 3 HD voices and a short Python script, plus the bits that went wrong.

Why not just use recordings?

I wanted one clean, consistent clip per sound. I went looking for recordings someone had already shared, but couldn't find anything clearly licensed for reuse that suited this:

  • A few GitHub repos have audio for each kana, but with no licence, or no idea where it came from.
  • MIT OpenCourseWare has hiragana listening sheets, but they're non-commercial only and mostly cover words, not single kana.
  • Big open datasets like Common Voice (CC0) and Tatoeba (mostly CC BY) are full sentences, which aren't much use for single-kana clips.

So generating them with text-to-speech was the practical way to go.

Picking a service

I looked at OpenRouter's text-to-speech models (OpenAI's GPT-4o Mini TTS, Gemini TTS and Mistral's Voxtral), plus Google Cloud and Azure. I went with Google Cloud Text-to-Speech and its Chirp 3 HD Japanese voices. They sound natural, and the free monthly allowance covers this easily, since all of hiragana is only a few hundred characters of text.

Step 1: Set up Google Cloud

  1. Sign up at console.cloud.google.com.
  2. Make a project. I called mine hiragana-tts.
  3. Link a billing account to it. The API won't work without one, even though this job should cost next to nothing on the free tier.
  4. Search for Cloud Text-to-Speech API and click Enable.

Step 2: Make an API key

An API key is the simplest way to call it from a script:

  1. Go to APIs & Services → Credentials.
  2. Click + Create credentials → API key. Skip the "Help me choose" wizard, which only offers OAuth clients and service accounts.
  3. Click Edit API key, and under API restrictions pick Cloud Text-to-Speech API. That way, if the key ever leaks, it can't be used for much else.
  4. Copy the key and keep it out of anything you share or commit.

Step 3: The script

The script only uses Python's standard library. It has a table mapping romaji names to hiragana, sends each kana to Google, and saves what comes back as out/<romaji>.mp3.

The request looks like this:

body = json.dumps({
    "input": {"text": "あ"},
    "voice": {"languageCode": "ja-JP", "name": "ja-JP-Chirp3-HD-Aoede"},
    "audioConfig": {"audioEncoding": "MP3"},
})
# POST to https://texttospeech.googleapis.com/v1/text:synthesize?key=YOUR_KEY

You get JSON back with an audioContent field holding the audio as base64, which the script decodes and saves.

The key comes from an environment variable, so it never ends up in the code:

export GOOGLE_API_KEY=your-key-here
python3 generate.py a ka shi   # try a few first
python3 generate.py            # then do the lot

You can also set VOICE to try a different Chirp 3 HD voice, and OUT_DIR to save somewhere else.

Things that went wrong

A silent clip. My first test gave me an almost silent shi.mp3: 0.34 seconds and 1.3 KB, when ka was 0.86 seconds. Running exactly the same request again gave a good one. Chirp doesn't give the same output every time, and really short single characters with no voiced sound in them can sometimes come back nearly empty.

So now the script checks each result. If a clip is under 2000 bytes, it has up to three more goes, keeps the biggest one, and warns me if it's still short. The 2000-byte cut-off is just a rule of thumb from the first few clips, so now and then it'll retry one that was actually fine.

One that just wouldn't work: え. On the full run, い, き and え all came back near-silent. い and き were fine when I re-ran them, but え failed even after three retries, so it wasn't just bad luck. Giving the voice a tiny bit more context sorted it. The script has a TEMPLATE setting that wraps the kana before sending it, and sending え。 (with a Japanese full stop) gave a good clip:

OUT_DIR=fix TEMPLATE="{}。" python3 generate.py e

Then I copied that over out/e.mp3. Other things I could have tried: saying it twice ({}、{}, but you'd need to trim it afterwards), stretching the vowel ({}ー, which changes the sound), or just using a different voice for that one clip.

Single kana are a bit risky with any text-to-speech. One character on its own has no context, so the voice can read it oddly. Chirp 3 HD doesn't support SSML either, so there are fewer ways to force a pronunciation. It's worth listening to them, especially は, を, ん, ふ, じ, ぢ and づ. If one's wrong, you could send the kana inside a short word and trim the audio down, or switch to a Neural2 voice, which does support SSML.

Checking them

Once everything was generated, I sorted the files by size to spot any suspiciously small ones, then listened to a handful, especially the quiet unvoiced sounds and the awkward ones above:

ls -l out/ | sort -k5 -n | head
afplay out/shi.mp3   # macOS

Tidying them up for the app

Straight out of Google, most clips had about 0.4 seconds of silence at the start, which felt like a lag after tapping play. Before they went into the app, each one had the silence trimmed off both ends (leaving a tiny bit of breathing room), had its volume levelled so they're all equally loud, and was saved as a small mono MP3. They're about 4 KB each.

Cost and licensing

  • The whole set is a few hundred characters, well inside Google's monthly free allowance for Chirp 3 HD. Prices and quotas do change though, so check Google's site.
  • If you're planning to share the clips (in an app, or as a download), have a read of Google Cloud's terms and the Text-to-Speech terms on generated audio first. I haven't been through them in detail.

Other options

  • Azure AI Speech (for example ja-JP-NanamiNeural) has better SSML support, which helps if you need to pin down how a single kana is said.
  • VOICEVOX is free, runs on your own computer and doesn't need an account. Each of its voices has its own terms, and they usually ask for a credit.
  • OpenRouter has text-to-speech models through an OpenAI-style /audio/speech endpoint, but I haven't tried how well they cope with single Japanese kana.
